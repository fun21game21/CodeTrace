# Локальная установка CodeTrace 1.0.0

Требуются обычный **CPython 3.13.16 с GIL, без JIT**, Node.js 24+ (проверка на
24.19.0), pnpm **11.19.0** и запущенный Docker Engine / Docker Desktop.
Проверяемая платформа — macOS arm64. Linux использует те же POSIX-команды,
но отдельная проверка Linux в этом релизе не проводилась; Windows не проверялся.
Образ собирается для текущей архитектуры Docker. Не включайте эмуляцию иной
архитектуры без самостоятельной проверки времени и памяти.

Команды ниже выполняются из корня полученной копии репозитория. `python3.13`,
`node`, `pnpm` и `docker` должны быть в PATH. Установка зависимостей может
обращаться к package registries, сборка образа — загружать Docker base image.
Установка без сети не обещается. После установки облачные сервисы не нужны.

## Сборка и установка

Следующий блок является путь установки из чистой копии репозитория.
Каталог `dist/local` должен отсутствовать: установщик не перезаписывает установку.

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
pnpm install --frozen-lockfile
pnpm build
.venv/bin/python -m pip wheel --no-deps --no-build-isolation --wheel-dir dist .
.venv/bin/python backend/scripts/build_runner_image.py
.venv/bin/python scripts/install_local.py dist/local
```

Образ `codetrace-runner:1.0` собирается и проверяется один раз, включая точную
версию Python, GIL/JIT и UID 65532. Реальный image ID записывается в локальный
`backend/local-image.json`; файл не включается в Git. Backend проверяет identity
через Docker Adapter и никогда не выполняет pull/build при нажатии «Запустить».

`dist/local` содержит production assets, wheel, identity и отдельный venv с
установленным backend. Базовый wheel требует только зависимости contracts/Runner;
FastAPI, Uvicorn и websockets объявлены в extra `backend`. Установщик ставит
полный проверенный `requirements.lock`, включающий этот extra и инструменты проверки.
Wheel сам по себе не содержит frontend: пути к assets и
identity задаёт небольшой launcher через существующие `CODETRACE_FRONTEND_DIST`
и `CODETRACE_IMAGE_IDENTITY`. Runtime не импортирует Python из исходного проекта.
Не перемещайте готовый venv; для другой директории выполните установщик заново.

## Запуск и завершение

```sh
dist/local/venv/bin/python -I dist/local/run.py
```

Откройте **http://127.0.0.1:8000/**. Для запуска из другой рабочей директории
укажите абсолютные пути к `dist/local/venv/bin/python` и `dist/local/run.py`.
Launcher вычисляет пути относительно собственного файла. Vite при работе продукта
не нужен. В другом терминале проверьте:

```sh
curl --fail http://127.0.0.1:8000/api/health
```

Ответ должен содержать `available: true` и `pythonVersion: "3.13.16"`.
Выберите пример, нажмите «Запустить», дождитесь TRACE READY и проверьте шаги.
Завершение — **Ctrl+C** в терминале backend. Штатный shutdown прекращает активный
Run и очищает принадлежащие backend контейнер и временный результат.

## Если что-то не работает

- **Docker недоступен:** запустите Engine/Desktop и нажмите «Проверить backend».
  Редактор и локальная история остаются доступны; Run не имитирует успех.
- **IMAGE_UNAVAILABLE:** выполните сборку образа и новую установку, чтобы скопировать
  актуальный identity. Подмена тега другим образом не проходит проверку image ID.
- **Порт 8000 занят:** завершите известный вам процесс, занимающий его. Второй backend
  завершится с ошибкой привязки; автоматического перехода на другой порт нет.
- **Неверная версия Python:** проверьте `python3.13 --version`. Для воспроизведения
  проверенного пути используется ровно 3.13.16; Runner дополнительно проверяет себя.
- **История отсутствует:** IndexedDB принадлежит профилю браузера и точному origin.
  `localhost`, `127.0.0.1` и Vite 5173 имеют разные хранилища. Приватный режим и
  очистка данных браузера могут удалить историю. Недоступное хранилище показывает
  предупреждение и не блокирует выполнение.
- **TRACE READY не появился:** прочтите сообщение о запуске/загрузке. Повторная
  загрузка результата делает GET, а не повторно исполняет Python; результат имеет TTL.

Исходники Python, ввод и trace не отправляются в облако. Пользовательский Python
выполняется в контейнере с отключённой сетью. Это не утверждение, что произвольный
враждебный код абсолютно безопасен; модель изоляции описана в [README](../README.md).
